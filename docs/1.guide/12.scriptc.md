# scriptc (Experimental)

> Compile a srvx server to a native executable with scriptc.

> [!WARNING]
> Both [scriptc](https://scriptc.dev) and this adapter are experimental. Expect breaking changes and missing features.

[scriptc](https://scriptc.dev) compiles TypeScript and JavaScript to native executables, with no Node.js at runtime. It implements `node:http` and the web `Request`, `Response`, `URL` and `Headers` globals.

The default Node.js adapter relies on runtime tricks that scriptc can't compile, so srvx ships a separate adapter for it. Import it explicitly from `srvx/scriptc`:

```ts [server.ts]
import { serve } from "srvx/scriptc";

const server = serve({
  port: 3000,
  fetch(request) {
    return Response.json({ hello: "world" });
  },
});

await server.ready();
```

Build and run the executable:

```sh
npx scriptc build server.ts -o server
./server
```

The adapter only uses `node:http` and web globals, so the same file also runs under Node.js, which is handy for development and tests.

## Supported

- [Server options](/guide/options): `fetch`, `middleware`, `plugins`, `error`, `port`, `hostname`, `manual` and `silent`.
- [Server instance](/guide/server): `runtime` (`"scriptc"`), `url`, `fetch`, `serve()`, `ready()`, `close()` and `waitUntil()`.
- Streamed request and response bodies, multiple `Set-Cookie` headers, custom `statusText`, `HEAD` requests and null body statuses.
- `request.signal`, which aborts when the client disconnects before the response is sent.
- Errors thrown by the handler answer `500` (or the response of the `error` handler).

`FastURL` and `FastResponse` are the native `URL` and `Response`: scriptc's built-in classes don't need the Node.js adapter's optimizations.

## Limitations

- **Explicit import only:** scriptc resolves package exports with the `import`, `node` and `default` conditions, so `import { serve } from "srvx"` selects the Node.js adapter, which doesn't compile. srvx also declares a `scriptc` export condition, used once scriptc supports one.
- **No request extras:** scriptc can't add properties to a native `Request`, so [`request.ip`](/guide/handler#requestip), [`request.waitUntil`](/guide/handler#requestwaituntil), `request.runtime` and `request.context` are always `undefined`. Use [`server.waitUntil()`](/guide/server#serverwaituntil) for background tasks. Libraries that rely on these properties won't work.
- **HTTP/1.1 only:** the `tls`, `protocol` and `node` options are ignored (no HTTPS or HTTP/2).
- **Ignored options:** `gracefulShutdown` (not available, stop the process with a signal), `trustProxy`, `maxRequestBodySize` and `reusePort`.
- Streamed responses are written without waiting for the client to read (no backpressure), and bodies use chunked transfer encoding unless the response sets `Content-Length`.
- Applications are compiled from the published JavaScript of `srvx`, so scriptc warns that the adapter uses untyped values (`SC6101`) and compiles `middleware` and `plugins` arrays as checked-dynamic values (`SC6104`). This affects speed, not behavior.
