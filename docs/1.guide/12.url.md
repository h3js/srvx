# FastURL

> A faster `URL` for parsing request targets.

`srvx` exports `FastURL`, a [`URL`](https://developer.mozilla.org/en-US/docs/Web/API/URL) wrapper that lazily parses its input. For an origin-form request target (a path with an optional query, such as `/path?query`), access to `pathname`, `search`, `searchParams`, `protocol` and `hash` is significantly faster than a full `new URL()` parse, which matters on hot paths like request routing. Origin-form input resolves against `http://localhost`.

```js
import { FastURL } from "srvx";

const url = new FastURL("/path/to/resource?query=string");

url.pathname; // "/path/to/resource"
url.searchParams.get("query"); // "string"
```

`url instanceof URL` is `true`. Any access outside the fast-path properties, and any setter, transparently deoptimizes to full native `URL` parsing. Mutating `searchParams` does the same (mutations are reflected in `search`/`href` with native `URL` semantics). An absolute URL string (such as `https://example.com/path`) is always parsed with the native `URL` parser, so it gets no speedup.

> [!NOTE]
> The input is assumed to be an **already encoded** request target. For a string that starts with `/`, `FastURL` falls back to full native `URL` parsing only when it contains one of: `#`, `"`, `'`, `<`, `>`, a control character (`U+0000` to `U+001F`), a space, `U+007F` (DEL) or any non-ASCII character. Everything else is kept as-is and is not normalized the way `new URL()` would, including dot segments (`/a/../b`, `%2e`), backslashes (`/a\b`) and characters such as `{`, `}`, `^` and `` ` ``.

The lazy implementation is used on Node.js, Deno and Bun. On every other runtime, `FastURL` is a plain alias of the global `URL`, which does not accept origin-form input without a base URL.
